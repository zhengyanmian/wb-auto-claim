# WorkBuddy 每日自动领积分

Windows 上的一个小工具：每天定时把 WorkBuddy 左下角「Buddy加油站」卡片上的「立即领取」点掉，
并把每次执行的时间、结果写进本地记录，随时可查。

> 只做一件事——点那颗按钮。不注入进程、不改客户端文件、不碰网络请求，纯屏幕识别 + 鼠标点击。

## 为什么不能「看到按钮就点」

2026-10 版本更新后，左下角变成**三张卡片轮播**（每张停约 7.5 秒，一轮约 22.5 秒）：

| # | 标题 | 副标题 | 按钮 |
|---|---|---|---|
| ① | Buddy加油站 | 每日可领 **100** 积分 | 立即领取 |
| ② | 积分包购买全面开放 | 200 积分起购 | 限时加购 |
| ③ | 做任务赢积分好礼 | 连登抽取 Buddy 周边 | 立即前往 |

**三张卡的按钮长得一模一样**，都是白色实心药丸。任何「找一个白按钮然后点」的策略命中率只有 1/3，
剩下 2/3 会点到「限时加购」或「立即前往」——这正是本项目连续四天报「点了但状态没变」的原因。

稳定可分的特征只剩一个：**积分卡上有亮绿色数字 `100`**。

| 卡片 | 绿色像素（实测） |
|---|---|
| ① 积分卡 | 370 ~ 666 |
| ② 积分包 | 0 |
| ③ 做任务 | 0 |

但窗口底部头像、侧栏绿点也会贡献绿色（83 ~ 224 px），所以不能只数总量，判据收紧为
「**同一行上 ≥2 个、高 13~34px、宽 4~24px 的绿色小块**」——这才是数字该有的形态。

## 四种界面状态

| 内部状态 | 什么时候出现 | 脚本动作 |
|---|---|---|
| `claimable` | 轮到积分卡，按钮是白色药丸「立即领取」 | 双帧确认后点击 |
| `claimed` | 轮到积分卡，但按钮已是灰色药丸「今日已领」 | 判今日已领，直接退出 |
| `other_card` | 轮播正停在②或③ | 继续轮询，等它转回来 |
| `none` | 整个卡片区是空的（你把它收起了 / 活动结束 / 页面没加载） | 记 `no_card`，归为「待确认」 |

「已领」最通常的表现不是按钮变灰，而是**积分卡从轮播里被移除**——领到后那张卡就没了，
画面实测 51 秒零变化。所以还有一条判据：「只剩别的卡 + 画面静止 18 秒」或「整轮 35 秒都没转到积分卡」
都记为今日已领（本地记录里带 `claimed_by=cycle_absent`，说明是靠「缺席」推出来的，不是看到灰按钮）。

配套的三个细节：

- 轮播每张只停 7.5 秒，**必须轮询**（`cycle_wait` 35 秒内必转到），截一帧就下结论会随机踩空。
- 点击前**双帧确认**（间隔 0.15s、坐标差 ≤10px），防止切换瞬间点到隔壁卡片。
- 鼠标悬停在卡片上会**暂停轮播**，探测期间会把鼠标临时挪开，结束后还原。

## 快速开始

### 环境

- Windows 10 / 11
- Python 3.9+：`pip install opencv-python pillow numpy`

### 三步跑起来

1. **改 `config.json` 的 `app_path`** —— 指向你机器上的 `WorkBuddy.exe`
2. **改四个 `.bat` 里的 Python 路径** —— 里面硬编码了
   `C:\Users\<你>\.workbuddy\binaries\python\envs\default\Scripts\python.exe`，换成你自己的解释器
3. **双击 `run_now.bat`** —— 立即跑一次，看退出码和日志

### 挂成每天定时

双击 `install_task.bat` 注册计划任务 `WorkBuddy-AutoClaim`，默认 **09:00 / 12:30 / 16:30**（可在 `config.json` 的 `schedule_times` 里改）。

- 走的是 **任务计划 COM 接口**，不依赖 `schtasks.exe`（后者在部分环境下注册会「假成功」）
- 右键**以管理员身份运行**可额外挂上「解锁后 30 秒补跑」，解决锁屏那几次触发白跑的问题
- `install_task.bat --show` 查看已注册的触发点，`--no-unlock` 只注册定时

## 命令

```bash
python main.py                # 正常执行
python main.py --dry-run      # 只识别不点击
python main.py --probe        # 打印识别到的状态与坐标
python main.py --force        # 忽略「已领过」判断，强制点一次
python main.py --selftest IMG # 拿一张截图跑识别逻辑（离线自检）

python status.py              # 最近 7 天执行情况
python status.py --brief      # 一句话摘要
python status.py --days 30    # 看更久
```

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功领取 / 今日已领过 / 试运行 |
| 2 | 卡片不在（已收起 / 活动结束 / 未加载） |
| 3 | WorkBuddy 窗口没开也起不来 |
| 4 | 点过但状态不确定，需要人工看一下 |
| 5 | 脚本异常（堆栈见 `logs/`） |
| 6 | 当时是锁屏，解锁后自动补领 |

## 文件说明

```
main.py            识别 + 点击 + 记录，核心逻辑都在这里
status.py          按天汇总：已执行 / 已达成 / 未执行 / 未成功 / 待确认
install_task.py    注册/删除计划任务（COM 接口）
selftest.py        离线回归：识别用例 + 状态机分支
make_bats.py       生成 .bat（强制纯 ASCII + CRLF，避免 cmd 按 GBK 解析出乱码）
make_templates.py  重新采集识别样本
config.json        全部可调参数，每项都带 _注释
fixtures/          固定的识别样本（未领 / 已领 / 另外两张卡）
captures/          失败现场截图 fail_*.png（被 .gitignore 排除）
history.jsonl      每次执行的一条记录（JSON Lines，被 .gitignore 排除）
status.txt         状态页的文本快照（被 .gitignore 排除）
```

## 常见问题

**每次都是「锁屏」？**
锁屏时截到的是锁屏界面，点击也落不到应用上，脚本直接返回 6 而不是硬点。解锁后会有一次补跑
（需要注册时挂了「解锁后补领」触发）。

**为什么显示「待确认」而不是「未成功」？**
因为你可能领完顺手把卡片收起了——这时候界面上没有任何可读信号，报成「未成功」会把人往查错的方向引。
状态页会说明：若是你收起的，属正常；若当天还没领，展开卡片后下一次触发会自动补领。

**界面又改版了怎么办？**
脚本返回 4 并保存 `captures/fail_*.png`。拿这张图跑 `python main.py --selftest captures/fail_xxx.png`，
再对照 `find_claim_button()` 的判据调 `config.json` 里的 HSV 区间 / `pill_roi`，通常不用改代码。

**点完鼠标会不会乱跑？**
会保存原坐标，点完立刻还原；如果为了避开遮挡把窗口抬到了前台，结束时会把原来的前台窗口切回去。
